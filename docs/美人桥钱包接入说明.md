# 美人桥钱包上分：复用现有订单收款代码

2026-10-09用户确认：钱包上分的本单地址分配、到账检查与蓝盛美人桥订单复用同一套代码，不新增独立分配逻辑或收款监听服务。钱包仍为平台USDT/TRX账本，不等于每商户拥有链上钱包。

## 开发接入

1. 创建钱包上分订单后，调用现有美人桥订单的地址获取/分配代码，沿用该代码需要的订单、商户、币种及其他参数。真实方法名和返回字段应从现有后端代码核对，本Demo不定义新接口名。
2. 保存该次分配返回的地址、网络及现有分配标识，与钱包上分订单关联。展示本单地址、复制按钮及同一地址生成的二维码。网络以现有服务结果为准，Demo的TRON字段不能成为新增网络限制。
3. 查询记录、再次打开、刷新页面时读取本单已保存的分配结果，不重新分配或替换成其他订单地址。分配中、失败、有效期及地址回收遵循现有订单实现，不另建地址池、优先级、租约或调度规则。
4. 到账检查、币种与网络校验、链上确认、交易去重、少付/多付、异常与回执重试等直接复用现有美人桥订单代码。接入时核对原代码已有行为，不从原型新增一套规则。
5. 将现有代码核验通过的收款结果关联回钱包上分订单，以实际收到的原币数量扣除本单手续费后自动增加商户同币余额，写入订单及流水。重复回执不重复入账；正式实现需服务端事务与幂等保护。
6. 只复用收款链路，钱包入账保持USDT入USDT、TRX入TRX，不复用旧订单的CNY金额换算。商户无“我已付款”确认步骤。

## 原型边界

源文件为 `src/pages/美人桥商户钱包/美人桥商户钱包-demo.html`；`createTopup`保留订单收款信息，`collectionInfo`统一订单结果页与详情展示，`receiveTopup`模拟已校验回执后的净额入账。

本地仓库没有真实地址分配或到账监听的后端代码，现阶段沿用既有美人桥订单Demo的两种演示地址，并为这些地址生成对应二维码。它们不是生产地址，也不代表每单都固定复用同一地址的业务规则。未创建新的分配算法或监听器，真实接入需替换为上述既有服务返回结果。历史Demo记录只补展示信息，不覆盖已记录地址或改变余额。

## 验收

- 正常与重复收款通知使用现有检查代码，钱包原币净入账且不重复记账。
- 分配、收款异常沿用现有实现；正式服务、有效期及回执字段在开发代码中核对，不由Demo虚构。

当前33项自动检查通过，包含地址随订单持久化/重复打开/不覆盖已分配结果验证。浏览器验证复制及详情，独立二维码解码器确认USDT/TRX页面截图编码与展示地址一致。仅本地演示，未执行链上转账。
