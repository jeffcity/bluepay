# 美人桥钱包一期接入说明

## 本期范围

- USDT充值、余额、钱包余额上分及充值订单／钱包流水；自动到账异常时支持后台人工确认入账、取消。
- **充值不收手续费，实际收到多少 USDT 就入账多少。** 不新增全局或商户钱包充值费配置，不影响其他业务费率。
- TRX 充值、USDT 兑换 TRX、汇率配置及能量租赁延期；旧演示数据保留，不作为一期入口。

## 复用现有收款链路

1. 创建订单时复用现有美人桥地址获取、分配代码，保存本单地址、网络及分配标识。真实方法和字段由开发核对，不在 Demo 中另定接口。
2. 本单地址文字、复制结果、二维码须一致；刷新或重开详情读取已分配结果，不重新分配、不串用其他订单地址。
3. 复用现有查链、币种／网络校验、确认、交易去重、异常与通知重试；不另建地址池或监听服务。地址有效期、少付／多付／分次到账与取消后到账的完成条件需核对原规则并经产品确认。
4. 确认实际收款后，全额增加商户 USDT 余额，写成功订单和一笔入账流水；不扣费、不换算 CNY。创建订单本身不改余额。
5. 自动与人工确认共用入账逻辑；状态、余额、流水同一事务完成，重复通知和并发操作只允许一个有效结果。

## 运营兜底与权限

- 仅待收款可手动确认或取消。确认填写收款核验说明，取消填写原因；保存操作人、方式、时间及证据关联。成功／取消后不重复处理。
- 人工确认须实际核实收款，按实际收款全额入账，不绕过服务端权限、状态及去重校验。失败不部分改余额或订单。
- 取消不记资金流水；取消后真实收款须保留核查记录，后续按最终确认的异常规则处理，不能直接丢弃。
- 同步钱包菜单、查询／详情、创建充值、手动确认及取消的按钮权限、接口鉴权和目标角色授权；商户仅看自己，后台限定美人桥业务。
- 服务端只接受本期 USDT 操作，拒绝 TRX 充值或兑换；隐藏入口不代替服务端限制。

## Demo 与真实服务的边界

- 页面源：`src/pages/美人桥商户钱包/美人桥商户钱包-demo.html`。`createTopup`创建零手续费USDT单，`collectionInfo`展示本单收款信息，`receiveTopup`和`manualConfirmTopup`模拟全额入账。
- Demo地址、二维码和收款通知均为演示，不发起真实转账；真实地址分配、到账监听、服务端事务及权限须接入现有后端。
- 旧待收款演示单显示全额，并在确认成功后记录零费及全额入账；已完成账本不追溯改写。生产若存在旧单，迁移范围和规则需单独核定。
- 验收至少覆盖100USDT入100、无手续费字段和配置、地址三者一致、重开地址不变、重复通知不加款、人工／自动／取消竞争及权限拦截。


## 钱包余额上分复用合同

- 复用现有美人桥业务订单、当前商户绑定、美人桥号／归属／代理、汇率费率及机器人MQ链路；只将本笔USDT收款来源改为钱包余额，不分配充值地址、不再等待链上付款。订单关联钱包扣款与退款流水，不能另建机器人处理系统。
- 后端静态快照依据：system模块的OrderPreDto.MerchantAmountItem、BridgeOrderServiceImpl.preOrder / autoHandler / sendAutoHandlerMessage。原USDT输入最多2位小数，按USDT×(基础汇率+浮动汇率)×(1+商户费率/10000)计算CNY，在整数元边界八舍九入。真实接入先核对线上版本；Demo不读取生产行情或发送MQ。
- 本地弹窗读取原Demo共享USDT/CNY配置和当前商户业务资料，默认值为演示。确认时重新核对快照；金额／商户绑定／规则变化时禁止按过期预览扣款。
- 钱包扣款、业务单及唯一扣款流水需同一事务；派送及重试沿用原链路，不能因MQ重投重复扣USDT。状态和金额由服务端校验，客户端金额或商户参数不可信。
- 机器人明确返回失败时，自动把本单扣除的USDT原额退回钱包，不需要后台核实或确认；结果不明／超时先保留扣款，等待最终结果。退款与订单终态、退款流水同事务提交，成功／退款竞争同一终态。退款后禁止再派送；迟到成功记录异常，不自动改写终态。
- Demo的creditOrders仅保存上分业务单展示快照；本地“机器人结果”折叠控件模拟成功／失败／未知回执，失败自动退款，不代表真实派送、服务端事务、审计或并发已接入。原订单管理／统计与真实共享业务单的联调由开发按既有接口完成。


## 付款来源与钱包流水边界

钱包不单列上分订单页签，上分业务单继续复用原订单流程。只有明确以钱包余额付款且存在匹配商户、业务单、USDT数量的扣款流水，才属于钱包上分；原机器人／其他资金来源的业务单不触发钱包扣款或退款。处理结果变动不新增账变，实际退款才新增一笔正向流水。失败回执只对存在匹配钱包扣款的本单自动原额退回，不能对无钱包扣款的机器人单退钱；无后台退款确认入口。

本地模型新增来源标记和匹配扣款流水校验；旧本轮模拟单仅在有真实匹配扣款流水时补标记，不迁移原机器人单或改写余额。正式服务端依据可信订单资金来源、扣款关联与唯一流水验证，不能信任客户端标记。
