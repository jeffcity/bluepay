# 业务页面迭代

## 1. 定位受影响页面

从 `src/catalog/project.json` 的产品导航中找到受影响页面，确认：

- 所属端：`后台`、`商户` 或 `地址池`
- 产品菜单名称与导航 `id`
- 当前页面源 `doc`
- 页面启动标识 `boot`
- 已关联需求 `req`

需求名称只用于追踪，不作为新建页面源的依据。

## 2. 更新既有页面

新增字段、状态、币种、筛选条件或交互时，直接更新该业务页面的现行源文件，并遵守：

1. 保留页面原有字段、操作、交互和已支持币种。
2. 不复制现行页面，不建立需求专属 `*-demo.html`。
3. 同一页面受多个需求影响时，继续共用同一 `doc` 与 `boot`。
4. 同时影响多个端时，在同一需求记录的 `moduleCodes` 登记多个端。

## 3. 登记需求追踪

在 `src/catalog/project.json` 中：

1. 新需求在 `pages` 增加唯一的 `BP-REQ-xxx` 记录。
2. 将需求编号加入所有受影响导航叶子的 `req`。
3. `pages[].doc` 指向承载该需求主要页面的现行源文件。

## 4. 真实新增页面

只有产品本身新增导航页面或独立端时，才允许新增页面源：

```text
src/pages/<业务页面或稳定页面组>/<业务页面或稳定页面组>-demo.html
```

新增后必须同时登记 `documents`、产品导航叶子及需求追踪。不得为了提供单独链接或方便评审而新增页面源。

## 5. 完整性要求

- 根 `index.html` 是唯一用户评审入口。
- `src/pages/` 下每个正式 HTML 页面源必须登记在 `documents`。
- 每个非静态导航叶子的 `doc` 必须存在，并关联至少一个需求编号。
- 需求资料目录只记录 Demo 仓库、统一入口和页面 route/hash，不保存正式 Demo 副本。
- 页面源不得包含账号、密码、Token、密钥、真实商户资料或生产接口地址。

## 6. 验证与交付

```bash
npm run check
```

检查通过后只交付根 `index.html`，并按产品菜单名称说明本次修改页面；不提供源码页或独立需求 Demo 链接。
